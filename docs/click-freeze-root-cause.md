# 点击无响应问题：根因与修复

## 根因

旧版 `translation/runtime-zh.js` 的 `MutationObserver` 回调直接调用全页面 `scan()`。游戏会持续刷新战斗数值、进度条、日志和提示；每次刷新都会遍历整个 `document.body`，并对每个文本节点执行完整术语替换表。翻译脚本本身没有拦截鼠标事件，但它长期占用 Electron 渲染线程，导致点击事件排队，表现为“界面显示正常但无法点击”。

另外，补充词条时曾漏写数组分隔逗号，导致 `R` 词表包含 `undefined`。遇到未命中的文本时，翻译循环会因读取 `pair[0]` 抛出异常，脚本从此停止，造成“完全没有汉化”。该结构错误已修复，并用 Node.js 运行时测试确认词表无空项。

## 修复

监听器现在只处理本次变更涉及的对象：

- 初次加载时扫描一次完整页面；
- 新增 DOM 子树只扫描新增子树；
- 文本变化只翻译变化的文本节点；
- `data-help`、`data-helptitle`、`aria-label`、`placeholder`、`title` 只更新发生变化的元素属性；
- 不再把每次 Mutation 当作全页面扫描请求。

这样保留动态日志、战斗和窗口内容的翻译，同时避免持续刷新阻塞输入事件。

## 回归证据

在临时游戏副本中使用重新打包的补丁完成了：安装后 ASAR 哈希变化、`game/zh.js` 存在、字体存在、CSS 已注入；随后运行卸载脚本，原始 ASAR 哈希恢复。使用的是 ZIP 内的 CMD 脚本，未传入任何参数。
