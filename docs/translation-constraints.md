# Lowmoor 汉化翻译约束

本文件是后续所有译文的强制规范。译文必须达到专业游戏本地化译者水平，不能按词典逐句直译，也不能只根据单句猜测含义。翻译者在提交前必须通读相关事件、章节、角色、系统说明和日志上下文，并保持前后一致。

## 语气与人物

- 保留原作的低魔奇幻、行会记录、冒险者手记气质。系统文本可以简洁，叙事、日志和角色台词要有明确语气。
- 同一人物的称谓、口头禅、礼貌程度、冷幽默和讽刺不能在不同窗口漂移。
- 不能把角色个性抹平成现代客服话术；不能擅自增加原文没有的解释、感叹或网络流行语。
- `Mereward`、`Guild`、`Maw`、`Mourning Vale`、`Lich` 等专名先建立术语表，再全局统一。专名是否音译、意译或保留英文必须由术语表决定。

## 连贯性与语境

- 章节、事件、任务、成就、装备、技能、宠物、雇佣兵和地名必须跨菜单、日志、提示框、图鉴、补丁说明保持同一译名。
- 数值、单位、时间、百分比、等级、骰面、快捷键和稀有度不能误译或改动。`HP`、`MP`、`XP`、`INT`、`WIS`、`CHA` 等机制缩写按术语表处理。
- “simple wording” 等选项是游戏机制名，不得在某处翻译成形容词、另一处翻译成按钮名。
- 对含糊代词、双关、讽刺、押韵、反复出现的意象，必须回看触发事件和前后句；无法确认时标记 `needs-review`，不要擅自定稿。

## 词梗与文体

- 英文双关、押韵、缩写梗优先用中文等效表达，同时保留功能和人物语气；无法等效时宁可保留关键意象并在译注说明，不要硬造脱离世界观的笑话。
- 补丁说明、成就名、章节名等短标题要简练；长提示可自然分句，但不能遗漏条件、例外和因果关系。
- UI 窄栏中的短标签优先使用最短自然中文；长说明允许换行，不得为塞入一行而删减机制信息。

## 标记、占位符与格式（不可破坏）

- 原文中的 HTML 标签、实体、`<b>…</b>`、换行、插值（如 `${name}`、`{count}`、`%s`）、数字格式、控制字符和快捷键标记必须原样保留并放在语义对应位置。
- 不得翻译 DOM `id`、CSS 类名、事件名、存档键、Steam token、文件名、URL、版本号、枚举值或内部键。
- `old` 必须是可定位的完整原文，`expected_count` 必须准确；同一句在不同语境含义不同，必须拆成不同清单条目并附上下文。
- HTML 属性 `data-help`、`data-helptitle`、`aria-label`、`placeholder` 属于玩家可见或无障碍文本，必须翻译；纯装饰 SVG、CSS 选择器和图标路径不翻译。

## 交付与审校

- 译文填入 `translation/patch-manifest.json`，每条包含 `path`、`old`、`new`、`expected_count` 和简短 `context`。
- 提交前进行三轮审校：术语一致性、上下文/人物语气、标记与占位符完整性。任何一轮失败都不得进入补丁包。
- 正式发布前必须通过静态可见文本、动态模板、格式、资源覆盖四项审计，并在临时游戏副本上验证安装、封包提取和卸载回滚；不得直接用开发中的原始游戏封包做试装。
