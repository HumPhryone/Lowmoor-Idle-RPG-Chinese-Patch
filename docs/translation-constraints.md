# Lowmoor 汉化审校准则

适用于维护 `translation/zh-revisions.json`，即对官方简体中文的润色覆盖。术语以 `translation/terminology.tsv` 为准。

## 修改原则

官方译文整体可用，**只改真正有问题的条目**，不做同义替换式的改动。以下情况需要修改：

- 误译或漏译：条件、例外、数值、因果关系出错或缺失；
- 残留英文；
- 术语不一致；
- 语气错位：公会簿记腔被译成客服腔或说明书腔，冷幽默、双关、官僚幽默丢失；
- 翻译腔、读不通；
- 与设定冲突。

专名如需改动，必须全库同步，包括所有语法变格副本。

## 游戏背景（据游戏文本整理）
- 零玩家/放置 RPG，仿 *Progress Quest*。玩家在**梅尔沃德（Mereward）**的**冒险者公会（the Guild）**登记，选种族（folk）、职业（trade）、出身（origin），然后看**纪事（chronicle）**自动推进。界面仿 Windows 98 等老桌面。
- 叙述者是公会的簿记腔：一切都被“登记、入账、划去、盖印、按章程付款”。柜台后的**佩尔先生（Master Pell）**收购战利品、按**章程（charter，公会规章）**付钱。公会有**名册（the Roll）/荣誉名册（Roll of Honour）**、编号**身份牌（tag）**、绞盘（windlass）、公会钟（bell，为失踪队伍鸣钟）。冒险者“下行（descent）”，层层深入。
- **模块 I：巨口（The Maw）** —— 梅尔沃德城外的巨大竖井地城，30 层、五个篇章（Arc）：地精巢穴、废矿、冢下墓窟、沉水地庙、巨龙宝窟（赤龙马尔格里斯）→ 深门（Undergate）、碎碑原、下方言者 → 仿造镇、假公会长、镜廊、分身者瓦斯蒂安的观测所 → 地下名册库（The Roll Below）、七守陵廊、债徒深狱、最后密室的巫妖（最后一位诚实的守封者） → 破碎封印、无记之层、锁链暗域、**巨口之底（The Bottom）**与“深处之债”沃伦。核心母题：**计数（the count / tally）、封印（seals）、七位守封者（wardens）、债（debt）**——巨口是为埋葬一笔“债”而挖；守封者一季一季守着计数。结局二选一：计数续守（the count kept）或债务清偿（the debt discharged）。
- **模块 II：哀恸谷（The Mourning Vale）** —— 哥特式荒原山谷：荒原道、峭崖下的霍洛米尔、荆棘泽林、白骨果园、泣水沼、犬舍与外墙、科尔文城堡；伯爵科尔文、伊斯米尔新娘、维尔嬷嬷、圣奥德尔修道院的未获赦院长等。以“夜（nights）”计时，有四种“答复（answers）”作为结局。
- **模块 III：最后的锚地（The Last Anchorage）** —— 航海篇：寻找失踪的**艾奥娜·里德船长（Captain Iona Reed）**远征队；领航员阿尔达、外科医生玛拉、船匠霍布；对手是**马雷克·韦恩提督（Admiral Marek Vane）**与红帆海盗（corsairs）；海图、灯塔、假灯标、风暴带、护航难民船队。
- 专名大量来自 D&D SRD 5.1（怪物、法术），遵循国内 D&D 通行译名习惯。

## 文风要求
- 叙事/环境描写/日志：简洁、冷峻、带书面感，可用少量文言节奏（“之”“其”“乃”适度），不堆砌辞藻，不加原文没有的感叹与解释，不用网络流行语。
- 官僚幽默要保留：原文一本正经地把冒险写成文书流程，中文也要一本正经（“按章程”“登记在册”“划去”“盖印”）。
- UI 短标签：最短自然中文；机制说明：准确第一，条件、数值、例外一个不能丢。
- 标点用中文全角（，。：；“”？！……），与相邻片段衔接处保持官方原有写法。数字与中文之间不加空格（沿用官方）。引号用官方使用的样式（官方多用「」或“”——同一条内保持一致，不要与官方同批次的其他条目混用风格）。

## 格式铁律（违反会导致游戏无法启动）
1. `{name}`、`{value1}`、`{tag3}`、`{markup1}` 等占位符：**一个不多、一个不少、原样保留**，可调整位置以适应中文语序。`{tagN}` 通常成对包裹一段文字（开/闭标签），调整语序时开闭成对移动，顺序不能颠倒。
2. HTML 标签、实体（`&amp;`）、`\n` 换行、前后空格：保持与官方中文**相同的开头/结尾**。很多字符串是**拼接片段**（以逗号、“，”、空格开头，或不以句号结尾，如 `", and the counter pays {value1} gold pieces..."`），它们与相邻 key 拼成一句——片段只修正明确错误，**开头与结尾的标点/空格保持官方原样**，不要擅自加句号或删逗号。
3. 同一英中组合常以语法变格副本出现在多个键（`grammar.*`、`declension.*`、`narrative.monster.modifier.*`），修改时要同步所有副本。
4. 纯技术字符串（ID、CSS 类、URL、`Bearer {value1}` 之类）不要动。
5. 人名：随机人名、兽名音译为中文（参考 `glossary_terms.tsv` 与已有 NPC 译名风格，如 阿尔达、里德、韦恩），昵称型名字（Nettle、Cinder、Tuppence）可意译或音译，取自然者。
6. `select` / `plural` 对象要保持官方的 key 结构，只改叶子字符串。

## 提交前检查

提交前依次运行：

1. `node tools/Build-Override.js locales.json`：检查键是否存在、占位符是否与官方一致；
2. `node tools/Validate-Patch.js <解包目录>`：用游戏自身的 `registerLocale` 做实际注册校验。

两项都通过后才能发布。
